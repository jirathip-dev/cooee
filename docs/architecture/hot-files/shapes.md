# The shapes

What each collected file exports, what the generator writes, and the two new Rust types. Names are final; bodies are
sketches. All of it is on the tree after #189.

## What a collected file exports

| Folder | One file is | It exports | The index |
|---|---|---|---|
| `crates/cooee-core/src/` | a core module | its `pub` items | `lib.rs`, generated |
| `crates/cooee-server/src/` | a server module | its `pub` items | `lib.rs`, generated |
| `crates/cooee-server/src/routes/` | an area's HTTP routes | `pub(super) fn routes(b: RouterBuilder) -> RouterBuilder` | `routes/mod.rs`, generated |
| `crates/cooee-server/src/hub/` | an area's hub operations | `impl Hub { … }`, and `pub(super) struct State` if it keeps any | `mod` lines in `hub.rs`, by hand |
| `crates/cooee/src/cmd/` | a command, named by its file | `USAGE`, `FLAGS`, `run` | `cmd/mod.rs`, generated |
| `crates/cooee/tests/support/` | one concern of the test support | its `pub` items | `support/mod.rs`, generated |
| `docs/` | an area's doc | `## Today`, `## How it works`, `## API` | the README's `Today` list, generated |
| `ci/gates/` | a CI gate | a script that exits non-zero when the gate fails | none: `ci/gates.sh` globs |
| `apple/e2e/steps/` | a native e2e step | a script `run.sh` sources, in name order | none: `run.sh` globs |
| `apple/Sources/CooeeFeatures/Clients/` | a dependency client | the struct, its `testValue`, its `DependencyValues` accessor | none: SwiftPM globs |
| `apple/Sources/CooeeApp/Live/` | a client's live value | `extension <Name>: DependencyKey` | none |
| `apple/Sources/CooeeCore/Models/` | one API model | the type and its `Codable` keys | none |
| `apple/UITests/Live/` | a screen's live UI tests | its `LiveUITestCase` subclass and its helpers | none: a synchronized folder |

A Rust module that only one platform compiles says so itself (`#![cfg(target_os = "macos")]` as its first line), so
its index line never needs an attribute.

## The generator's input

`scripts/gen.sh` holds one line per generated file. It changes only when a new collected folder is made.

```text
crate   crates/cooee-core/src     private: accounts blocks chat config devices login providers root shed store
crate   crates/cooee-server/src   private: gate http hub login look manage pairing passkey plugin push root routes routines serve themes
routes  crates/cooee-server/src/routes
cmd     crates/cooee/src/cmd
flat    crates/cooee/tests/support
today   README.md  from docs/*.md
lock    Cargo.lock
```

Rules, the same for every kind: a module is a `<name>.rs` file or a `<name>/` folder (once when both exist); names
sort in the C locale; the output goes through `rustfmt`, so it is always `cargo fmt`-clean; running it twice writes
nothing the second time. A `private:` list is today's private modules and only shrinks: a module not on it is
`pub mod`.

## What it writes

A crate root (`lib.rs`). Its doc line no longer lists the areas (that sentence was edited seven times):

```rust
//! cooee's core: the model and its files. No HTTP.
// Generated by scripts/gen.sh from the files in this folder. Never edit: add a file and run `just gen`.

mod accounts;
pub mod history;
pub mod inbox;
mod root;
mod store;

pub use root::*;
```

`root.rs`, by hand, frozen. Today's `pub use` lines, moved as they are:


## The CLI's types (`crates/cooee/src/cli.rs`)

```rust
/// One command. Its file in `cmd/` exports everything but the name.
pub(crate) struct Command {
    /// The first word: the file's name.
    pub name: &'static str,
    /// Its part of the usage line.
    pub usage: &'static str,
    pub flags: &'static [Flag],
    pub run: fn(&Invocation) -> Result<(), Failed>,
}

/// A flag a command reads. As today, a flag is taken out wherever it stands on the line.
pub(crate) enum Flag {
    /// `--yes`
    Switch(&'static str),
    /// `--rev <r>`
    Value(&'static str),
}

/// Why a command did not finish.
pub(crate) enum Failed {
    /// The usage line on stderr, exit 2.
    Usage,
    /// `cooee: <why>` on stderr, exit 1.
    Because(String),
}

/// The parsed line: `--instance` and `--config` (global), the word, the flags found, what is left.
pub(crate) struct Invocation { /* private */ }

impl Invocation {
    pub fn rest(&self) -> &[&str];
    pub fn on(&self, switch: &str) -> bool;
    pub fn value(&self, flag: &str) -> Option<&str>;
    /// The instance's config, loaded once (the defaults when there is no file).
    pub fn config(&self) -> Result<Config, Failed>;
}
```

Today's words and their files: `accounts`, `devices`, `doctor`, `install`, `machine`, `mcp`, `pair`, `perf`,
`plugin`, `push`, `reports`, `secrets`, `serve`, `setup`, `theme`. A word's sub-commands (`plugin check`,
`devices rm`, `mcp proxy`) stay inside its file. `--version` and `--help` stay in `main.rs`.

## Scripts

A gate, `ci/gates/<name>.sh`: POSIX sh, `set -eu`, run from the repo root, its first comment line says what it
proves, it needs only what the `msrv` job installs. `ci/gates.sh [name…]` runs the named ones, or all in name
order; it runs every gate even after one fails, then names the failed ones and exits 1. Today's eleven recipes
become eleven files with the same commands: `fmt`, `clippy`, `test`, `doc`, `deny`, `cap`, `deps`, `hygiene`,
`neutral`, `themes`, `ci-scripts`.

An e2e step, `apple/e2e/steps/NN-<name>.sh`: sourced by `apple/e2e/run.sh`, which gives it `$E2E` (a temp folder
with `serve.log`), `$SIM` (the simulator it made) and `pair_link` (mints a fresh pairing link). `run.sh` starts the
server, makes the simulator, runs the steps, collects the screenshots and always tears both down; it deletes only
the simulator it made.
